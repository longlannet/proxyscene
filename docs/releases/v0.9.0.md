# proxyscene v0.9.0

本版集中修复配置恢复、用户命令环境、节点兼容性和 Telegram 接管问题，并更新 Go 与 Xray。保留原有节点、场景和持久化 ownership 的升级路径。

## 升级前须知

- **Hermes 消息保留策略**：运行中的 Hermes 网关只有在最终有效的 `drop_pending_on_cold_boot` 为布尔值 `false` 时，才允许由 proxyscene 为切换代理而重启。默认策略会丢弃积压消息；程序会拒绝不安全的切换，并保留重试记录，不会自动修改应用的业务配置。请将下面的字段合并到现有 Hermes 配置，同时检查 managed YAML、旧 `gateway.json` 和其他 Telegram 配置段没有覆盖它：

  ```yaml
  platforms:
    telegram:
      extra:
        drop_pending_on_cold_boot: false
  ```

- **Xray 更新**：固定为官方 **v26.9.9**，源码提交 `52a412d9e2f5c2a5142b1b4e2ab3771dacb8b120`，上游将该版本标为预发布。四架构归档和 ELF 均按仓库固定摘要校验；同版提供对应源码及全部链接模块的许可证。管理程序的源码构建需要 **Go 1.27.1**。 Xray 此版移除了 Shadowsocks `none/plain`；VLESS/Trojan 明文传输仅允许上游内建的私有/保留地址与本地域名。若正在使用这些模式，请在升级前切换到 TLS/REALITY 或支持的 AEAD 节点。不兼容的旧节点仍可读取、删除和替换，但新导入和启用会被拒绝。
- **接管范围更明确**：Hermes 多 profile、会绕过 Telegram 代理的 `NO_PROXY`、无法确认的环境/配置覆盖，以及 OpenClaw 账号级代理覆盖或 `$include` 会被明确拒绝。遇到冲突应按错误信息处理配置，勿删除 ownership journal 绕过保护。
- **状态不等同于连通性**：`status` 区分配置与服务状态；OpenClaw 热重载确认表示网关报告新配置和账号就绪，不代表真实 Telegram 端到端收发验证。

## 修复与改进

- Git/npm 开发代理按记录的用户身份操作精确配置文件，保护并发管理员修改，修复 npm 配置重定向和 Git 恢复竞争；失败和崩溃后可继续恢复。
- 用户命令使用最小环境及记录的 HOME/UID/GID，避免继承调用者凭据和运行时注入变量；损坏的非对象主状态可从健康备份恢复。
- 修复 Shadowsocks 密码中的百分号、`+`、`@` 处理；REALITY 公钥统一为 Xray 支持的 Base64URL 编码；传输配置由固定 Xray 验证。
- OpenClaw 优先确认官方频道热重载，减少整个网关重启；不支持或超时才回退。共享配置的网关分别确认，并发身份、配置和 ownership 冲突保留日志并报错。未运行的服务不会被自动启动。
- 支持经验证的 OpenClaw 官方 Node 启动形式与内存参数、Hermes 官方停止钩子；补齐 Node/Python dotenv、`NO_PROXY` 和嵌套配置包含的检查。
- Hermes 的受管 drop-in 禁用 Telegram 辅助 fallback IP 发现；默认消息丢弃策略、未知服务状态和重启后未运行均不会被误报为成功。
- Telegram 接管按每个目标组织准备、重载、确认和提交；合并重复解析，将 OpenClaw 上游状态观察与持久事务解耦，保留失败重试和旧版恢复语义。
- 安装文档的下载、身份及 checksum 校验失败会立即停止；CI 增加文档 bootstrap 负例，发布产物绑定 Xray 实际工具链、完整依赖和对应源码，并拒绝损坏的源码缓存。

## 发布产物与验证边界

提供 Linux amd64、arm64、386、armv7 的管理程序包和离线 bundle，以及 `install.sh`、`checksums.txt`、`xray_source_v26.9.9.tar.gz`，共 11 项资产。完整性模型为 GitHub immutable Release 与 SHA256，不提供独立发布者签名。

发布流程要求完整 Go/race/静态及漏洞检查、安装器与文档 bootstrap 测试、两次四架构构建逐字节一致、产物与源码校验，以及一次性 Debian 13/systemd 安装、v0.7.1/v0.8.0 升级、崩溃恢复和卸载测试。arm64、386、armv7 的交叉构建及 ELF/源码验证不等同于目标硬件上的运行测试；隔离网关夹具不等同于真实 Telegram 收发。服务外 CLI 和上游独立发送工具也不属于禁止直连保证。
