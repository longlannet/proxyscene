# proxyscene v0.10.0

新增订阅刷新、自更新及整理后的交互菜单，并修复发现、退管和失败恢复之间的安全边界。服务发现和完整预检在生产修改前完成；事务失败或进程中断后，仅恢复本次固定资源，不重新发现或接管其他目标。

## 新功能

- 新增 `subscription list`、`subscription update <序号或ID>` 和 `subscription update --all`；订阅管理支持刷新单个或全部已保存来源，先完成下载与校验，再一次性提交；保留手工节点、当前使用节点及其他订阅仍引用的节点。
- 新增 `update --check`、`update [--yes] [--source github|mirror]` 及菜单入口，CLI 与菜单复用 GitHub immutable Release 身份、资产摘要及离线 bundle 校验，明确展示版本和升级影响。
- 梳理主菜单、节点和订阅交互：选择绑定实际 ID，执行前展示影响，取消、EOF 和确认期间状态变化均不提交。

## 修复与恢复

- 区分服务不存在、mask、悬空别名、循环、I/O 失败与内容变化，严格传播 unit 字段解析错误；发现不完整或已选目标准备失败不会隐式撤销接管。
- Hermes 和 OpenClaw 按固定目标与可信身份执行；共享 OpenClaw 配置需要完整组授权，保留不相关字段及冲突证据。
- 增加持久运行事务记录，按本次实际前值逆序补偿 Global、Dev、Telegram 和核心变更。新增 `sudo proxyscene recover`；启动恢复遇到待恢复事务时仅续跑该计划并返回。
- Store 主文件作为提交点，主备通过比较后替换保护外部修改；补偿代号单调增加，主备未一致或存在冲突时保留记录。
- 核心免重启同时核对已加载摘要、有效 unit 与进程身份。正常升级允许仍运行的可信旧 Xray 进程切换到已安装新版；核心检查不扫描无关服务别名。明确重启后有界等待进程完成执行切换，避免 systemd 已返回但 Xray 尚未就绪时误判；已有进程与免重启校验保持严格。
- 已有安装的核心 unit、配置和权限纳入运行事务；开机恢复服务在运行配置提交后安装，其失败明确报告部分成功。

## 升级前须知

- 首次升级到本版仍使用旧版支持的安装器或离线 bundle；新自更新命令在安装本版后才可使用。默认从 `dl.ll.cd` 下载 bundle，GitHub 仍提供版本身份和可信摘要，不支持任意自定义更新源或强制降级。

- 悬空服务别名仍可能使预检拒绝继续；本版保证这类已发现错误不会先修改代理配置，并不会自动删除或忽略链接。
- 旧 Store 缺少历史 `RuntimeConfig` 且仍有核心运行状态、开启场景或接管证据时，拒绝猜测迁移。特别是 v0.7.1 等早期布局，需要先核验历史配置；不要补填当前参数或删除 journal 来绕过检查。
- 旧版系统级 Telegram 接管只有在历史运行配置、目标记录和文件内容均能证明归属时，才支持显式 `tg off` 后重新开启。仍含旧 EnvironmentFile 的直接 `tg on` 保持保守拒绝；没有稳定用户身份的旧用户级记录仍需人工核验。
- `recover` 只能消费完整的运行事务记录，不能凭空修复无历史依据的旧 pending。遇到外部文件、身份或 Store 冲突，先核验并解决冲突，再按提示恢复。
- 安装器先提交已校验的管理程序及 Xray，随后初始化服务。初始化或补偿失败不表示二进制已回退；恢复旧配置时使用已安装版本，并预先验证兼容性。
- 自定义核心 drop-in、核心服务别名或无法明确验证的执行覆盖会被保守拒绝。Hermes 消息保留策略和用户/文件权限要求保持有效。
- `tg on`、`install --skip-node`、`boot-restore` 和 `recover` 都可能修改配置或协调服务，不是只读检查命令。

继续使用 **Go 1.27.1** 与固定 **Xray v26.9.9**（上游预发布版）。本次未升级 Xray 依赖。

## 发布验证与资产

门禁包含普通用户和 root 安全回归、race、静态和漏洞检查、两次四架构构建逐字节比较，以及隔离 Debian 13/systemd 安装、active 升级和故障恢复测试。v0.7.1 验证缺少历史运行配置时安全拒绝；v0.8.0 与 v0.9.2 验证受支持升级。

正式发布顺序为 GitHub 检查、immutable Release 发布及独立公开验证成功后，再同步 `dl.ll.cd`、逐字节核验全部资产并更新 Latest。两处均完成才算发布交付。

提供 Linux amd64、arm64、386、armv7 管理程序和离线 bundle，以及 `install.sh`、`checksums.txt`、`xray_source_v26.9.9.tar.gz`，共 11 项资产。完整性模型为 GitHub immutable Release 与 SHA256，不提供独立发布者签名。隔离服务测试不等同于真实 Telegram 消息端到端验收，发布不会迁移维护者的宿主配置。
