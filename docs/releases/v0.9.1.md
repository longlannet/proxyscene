# proxyscene v0.9.1

修复 Hermes 官方系统安装被误判为不受支持的问题。程序目录由 systemd 最终有效的 `ExecStart` 自动识别，配置目录按服务用户和 `HERMES_HOME` 独立确定，无需新增配置项。

## 修复与兼容范围

- 支持原有 `<Hermes 配置目录>/hermes-agent` 布局及官方 `/usr/local/lib/hermes-agent` 系统布局；普通用户运行的服务也可使用可信的 root 安装。
- 系统安装的程序目录、`venv`、`venv/bin` 及可执行文件继续验证 root 属主和安全权限；对解释器文件的符号链接进行有界解析，拒绝不可信目录、链接循环和不安全目标。
- 程序目录必须存在；可选 `.env` 缺失仍允许。程序目录与配置目录的 `.env` 分别检查，保留代理覆盖、符号链接及非普通文件保护。
- 每次接管或恢复操作重新检测当前安装布局，支持用户安装与系统安装之间切换后的恢复；持久化 ownership 格式保持兼容。

## 升级前须知

从 v0.9.0 升级无需迁移配置。运行中的 Hermes 网关仍要求最终有效的 `drop_pending_on_cold_boot` 为布尔值 `false`；多 profile、无法确认的配置覆盖及不可信安装路径仍会被拒绝。任意自定义程序目录和间接启动包装器不属于新增支持范围。

本版保持 v0.9.0 的 **Go 1.27.1** 源码构建要求和固定 **Xray v26.9.9**（上游预发布版）。从更早版本升级时，请同时阅读 [v0.9.0 升级说明](https://github.com/longlannet/proxyscene/releases/tag/v0.9.0)，确认节点和 Telegram 消息保留策略兼容。

## 发布验证

发布门禁包含完整单测、race、静态和漏洞检查、root 安装权限测试、两次四架构构建逐字节比较，以及一次性 Debian 13/systemd 安装和升级测试。新增真实 Python venv 与受控 Hermes 模块夹具，验证实际模块来源、服务身份、配置目录、双向布局迁移及六类不安全路径或 `.env` 情况。

提供 Linux amd64、arm64、386、armv7 的管理程序包和离线 bundle，以及 `install.sh`、`checksums.txt`、`xray_source_v26.9.9.tar.gz`，共 11 项资产。完整性模型为 GitHub immutable Release 与 SHA256，不提供独立发布者签名。

运行时信任管理员维护的官方 Python 安装，不执行 Python 导入探测，也不证明任意 `.pth` 或导入钩子的行为。隔离网关夹具不等同于真实 Telegram 收发测试；交叉构建和 ELF 校验不等同于其他架构硬件上的运行测试。
